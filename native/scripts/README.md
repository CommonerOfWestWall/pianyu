# Android arm64 SpektraLab engine probe

This directory builds the upstream C++ engine at source commit `d90cf9a005d5c7eb4c0bc1eb9cac17459c2a9289` for `arm64-v8a`. The source tree is `work/engine-practice/SpektraLab`; its pre-existing dirty files were preserved and are not modified by this task.

Run `powershell -ExecutionPolicy Bypass -File .\build-android.ps1`. It uses NDK `28.2.13676358`, CMake `3.22.1`, the checked-in Vulkan-Headers and host glslang under `work/engine-practice/deps`, and builds with `SPEKTRALAB_BUILD_NATIVE_RAW=OFF` (no LibRaw). The resulting `spektralab_engine.so`, `spk_android_driver`, and Vulkan resources are copied here.

The driver accepts `resources input.f32 width height params.json output.rgba16 report.txt`. The baseline contract follows `work/film-practice/render_experiment.py`: input is tightly packed little-endian float32 RGB containing encoded sRGB values in 0..1, with `input_color_space=sRGB` and `input_cctf_decoding=true`; output is sRGB with encoding enabled. The fixed recipe is Kodak Portra 400 / Kodak Supra Endura with grain, glare and auto exposure disabled. It calls `spk_engine_create`, `spk_open`, and two `spk_render("full")` calls, prints create/open/first/repeat timings and returned dimensions, writes RGBA16 output, and records the backend report. Hash the output on host/device with SHA-256 after transfer.

Generate probes and desktop references with `python prepare_samples.py`. It uses the existing public `work/film-practice/inputs/kodim01.png` and produces 1024/2048 long-side speed probes under `samples/`; resizing is only for speed, while color comparison should use the original-size image. When the existing desktop fixture and resources are present, it also writes desktop RGBA16 references and reports.

The upstream checkout was already dirty at the recorded source commit: `engine/CMakeLists.txt`, `engine/src/gpu/vulkan_gpu.cpp`, `engine/src/pipeline/pipeline.cpp` were modified and `engine/src/shaders/vulkan/spk_highlight_headroom.comp` was untracked. Those files were not changed here. Resources are copied from the upstream engine resource tree and SPIR-V is generated by the pinned local glslang executable. The engine `.so` needs `libdl.so`, `libm.so`, and `libc.so`; the driver additionally needs NDK `libc++_shared.so`, which the build script copies here. `spektralab_engine.so` is the unstripped debug artifact; run `make-release.ps1` to create a stripped release copy and record its size. `deploy-adb.ps1` only prepares a later adb deployment and does not execute the driver.

No phone or APK action is performed by the build script. A real Vulkan result requires the later phone coordination step; this task only verifies cross compilation and driver linkage.

真机验证（2026-11-09）使用专用目录 `/data/local/tmp/pianyu-probe-20261109/`，设备 API 36 / Adreno Vulkan。部署成功，但 1024x683 在 `spk_engine_create` 的 Vulkan math probe 阶段退出码 1：`fma is not fused on a GPU device`；未写输出，2048 未继续运行。设备当时 battery 32.6 C、GPU 58.0/59.2 C、CPU 最高 88.0 C，现有 app 保持运行且未停止、清理或读取私人照片。完整记录见 `device-run-20261109.json`。这不是正式 benchmark；需要后续 Android 平台修复后再测。

数学探针诊断见 `math-probe-diagnostic.json`。设备读回 64 lanes 中 62 个 informative lanes 全为 `got=0`，CPU binary64 reference 的代表性 `want=7.45057349149647e-11`，因此已排除输入上传/索引错误，确认是 GPU 未融合 FMA。`check_math_probe.py` 是可执行的 CPU reference 回归检查；当前未把未经真机验证的 Dekker fallback 标成成功。

研究 overlay `android-unfused-fma.patch` 仅在该精确 zero-only 模式选择已有 Dekker specialization，并把 capabilities 明确标成 Android GPU unfused FMA。重新编译的 overlay 在真机 1024 和 2048 两档均成功完成首次与同会话重复渲染；与桌面 DLL 同输入、params、resources 对比，最大 U16 差异为 1，非零计数一致。详细数据见 `device-run-overlay-20261109.json`，实际 PNG 为 `results/android_1024.png` 和 `results/android_2048.png`。这仍是研究验证，不应替换产品发布核心。
