# OPPO Find X9：v9仍闪退的调查

目标：依据新反馈继续定位实际故障，不将捕获异常/降低尺寸等同为修复。设备不在本地，无ADB操作；用户随后提供v9本地退出诊断。

事实：v9导入后照片库预览一直转圈，点开后仍闪退，系统提示“运行内存占用异常”。源码确认库缩略图也调用完整胶片核心；Exception分支只写日志，UI在没有位图时始终转圈。native core串行，尚不能据此认定并行渲染、无限循环或驱动故障。

- [x] 将库浏览与胶片计算分开：优先读取当前编辑已保存的缩略图，否则只解码240长边原图并标“原图预览”，不将原图写入已调色缓存。
- [x] 显式区分缩略图读取中/失败/未生成，取消、错误和暂停不保留无限转圈；补充Android测试源。审核发现编辑时取消任务遗漏状态，已修正并补充断言。
- [x] 分开记录引擎初始化与图片处理阶段，避免初始化错误全归为预览。保留既有材料、参数、输出尺寸。
- [x] Worker只在研究目录运行当前Windows引擎240/960、full/live、grain0/.25实验，记录尺寸、native内存报告、时间和进程峰值。主线程审核16/16成功，未发现颗粒提高pool高水位，不用桌面结果断言手机原因。
- [x] 根据新诊断（LOW_MEMORY、180×240、RSS约6.9GiB）检查实际Android overlay，确认原本CPU专用的容量probe被放宽到GPU；Android构建精确移除probe调用，helper增加独立CPU guard。回归检查旧代码失败/新代码通过，实际核心便携重建63targets成功，35个shader与v9字节相同，旧probe特征在新核心消失。
- [x] 运行6项主机测试、Debug/Release/androidTest构建、lint（0errors/32warnings/1hint）；APK开发测试签名核对通过。
- [x] 核对最终源码与APK，打包待真机复测候选：867个源码文件逐字节匹配工作区、ZIP CRC通过，APK资产与核心匹配源码，签名沿用旧版开发证书，未推送或发布GitHub。
- [ ] OPPO复测导入、打开、切换风格与原尺寸导出；设备不在本地，未执行Android测试或复现/验收闪退。

主线程拥有app/UI/诊断/核心/文档/打包；worker拥有研究脚本与输出，后续只读审核。预期可观察结果：Android初始化不执行桌面大缓冲容量实验；进入照片库不触发胶片GPU计算；原图缩略图标识清楚，失败不转圈，关于/诊断可访问。OPPO实际结果仍需复测。
