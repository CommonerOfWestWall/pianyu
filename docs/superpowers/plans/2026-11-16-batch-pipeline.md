# 批量导入与导出修复 Implementation Plan

**Goal:** 在连接的Redmi K80 Pro复现用户的批量卡顿/失败，修复实际原因，保留原尺寸与既有编辑，交付经过设备验证的安装包。

**Architecture:** 沿用EditorModel协程、系统照片选择器、私有URI照片库、串行原生引擎与MediaStore输出。先测量导入元数据、缩略图、原尺寸渲染和编码各阶段，再仅修改有证据的问题；不通过默认降尺寸掩盖失败。

**Tech Stack:** Kotlin / Compose / Android ImageDecoder / Vulkan C ABI / Android instrumentation / Gradle。

## 已知事实与待证假设
- 手机24122RKC7C已连接；目前v12，库中6张HEIF；设备存储余量约76GB。
- 当前导入逐张查询名称及获取URI权限，在IO线程；缩略图240长边串行解码。批量渲染串行进行，但失败只计数、不向用户保留原因。
- `PhotoIO.finish`中多个私有中间Bitmap只在正常路径回收；异常路径是否积累内存须复现。
- HEIF原尺寸解码是否拖慢缩略图、原生渲染/编码是否造成失败，目前尚未判定。
- 上轮v13曝光/相纸改动保留；本轮不改材料模型，不动用户原片或历史配方。
