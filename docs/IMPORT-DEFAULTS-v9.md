# v9：导入故障与默认配方

## 故障和判断边界

用户报告 OPPO Find X9 打开导入照片时出现系统“内存使用异常”提示并闪退。没有该设备日志，尚不能确认是系统内存回收、Java内存分配、原生代码或Vulkan驱动故障。本轮无真机复现，不能称为修复已验收。

源码确认：导入先保存URI和编辑记录，编辑解码已限制长边960，并非直接将完整50MP照片送进核心。但JNI的 `bad_alloc` 原先一律提示“原尺寸照片过大”，连预览失败也会收到导出建议。这项误导已修正。

v9改动：

- 区分解码、胶片引擎、预览、导出错误。仅明确的OOM、`bad_alloc` 或Vulkan主机/设备分配错误视为分配失败；“不支持某种内存类型”和device lost不归为照片过大。
- 预览渲染分配失败时清空可再生成的位图缓存，最多降至640长边重试一次。缓存键包含实际尺寸，避免混用960和640的图像。降级只限本次预览，重新打开允许恢复960。导出仍独立读取原片，绝不自动缩小。
- 缩略图并发由2改为1；导出暂停缩略图。解码需要转换格式时立即释放私有中间位图，不回收仍由界面持有的图像。
- 引擎首次使用时初始化。异常退出后暂停自动生成效果缩略图，用户仍可进入“关于”复制诊断；打开照片是主动重试。
- 解码/原生处理前写入少量本地阶段信息。Android11+下次启动匹配系统最近主进程退出记录、PID和时间，区分LOW_MEMORY、CRASH_NATIVE、CRASH、ANR、SIGNALED。SIGNALED不等于内存耗尽，PSS/RSS是系统最后采样而非退出瞬间精确占用。
- 错误提示“查看”和“关于 → 处理诊断”可查看/复制最近报告。只保存设备、版本、阶段、错误及部分尺寸参数，不保存照片或URI，不自动上传。旧版没有阶段记录，不能追溯还原此前那次闪退。

诊断不能阻止驱动段错误或系统直接杀进程。OPPO上导入、颗粒、风格切换、重启诊断和原尺寸导出仍待实测。

## 默认强度为什么统一为100

原来的72/82/80/90/90/100/100是各风格经比较保留的材料混合权重，不是胶片准确度分数。直接将内部权重全改为1会改变效果。v9采用 `lookVersion=2`：界面100表示完整推荐配方，内部继续使用校准权重；额外完成层随相对强度变化，材料profiles不变。

新导入照片和切换到其他风格时使用100。保存过的v0/v1编辑按原语义读取，可能继续显示旧数值，不强行迁移。点当前已启用风格不会重置强度。关闭片屿预设并设100仍可查看完整材料模型。切换风格保留用户曝光、颗粒等调节。

## 上游默认与颗粒实践

核对的SpektraLab固定版本为 `0b5acfc4e45b7a946ed33a3c4b4e60429d208b66`。`app/SpektraLab/Sources/Model/FilmParams.swift` 的新帧默认：`autoExposure=false`、`exposureCompensationEV=0`、`grainActive=true`，颗粒强度1。导入从新帧默认开始。底层spektrafilm的Python默认AE与应用不同，不能混为一谈。

手机JPG/HEIF已经受曝光、HDR和色调处理影响。v9保持自动曝光关闭、胶片曝光0，不给所有照片叠加固定增亮。0EV不等于没套胶片响应；推荐配方本身的明暗处理仍生效。用户可分别调节“胶片曝光”和成片“曝光”。

本轮颗粒比较：3张输入（AI人像、公开真实手机街景、AI夜景）×7种材料×引擎颗粒0/0.25/1，共63张**桌面材料输出**。使用当前桌面核心、sRGB输入输出、960长边、35mm、EV0、AE关闭、256行分条。为单独看颗粒，关闭光晕、不应用片屿完成层及材料混合。因此它们不是新版默认配方的安卓验收样片。颗粒有随机性，不能当固定像素回归结果。

视觉检查全图和100%局部后，0.25增加轻纹理，1更明显。新照片暂取UI `grain=0.125`（约12.5/100，对应引擎0.25），可调至0或更强。这是审美起点，不是物理颗粒标定，OPPO性能仍未验证。实际效果还随材料混合和输出尺寸变化，缩略图中可能不明显。旧JSON缺失颗粒字段仍按0读取，显式保存的0保留。

桌面资源与APK源资源共有80文件，其中79相同；唯一不同是平台编译产物 `spk_math_probe.spv`，胶片、相纸和公共材料数据一致。原图、63张PNG、参数/哈希、联系表和脚本留在本轮桌面实验资料；不能将63次输出称为63张独立照片或安卓结果。

## 验证范围

主机测试覆盖七风格默认/部分强度的v1-v2等价性、旧满强度语义、用户调节、错误分类及导出提示。安卓测试新增持久化兼容和共用完成管线的像素等价检查，本轮只编译，未在设备运行。

构建、测试、lint和APK/源码哈希见候选目录 `verification.json` 和 `checks`。v7真机通过记录和介绍片仍属于v7，不能替代v9验证。
