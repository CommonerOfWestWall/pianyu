# v11：胶片前测光、推荐75与创作余量

## 从上游学什么

核对日期：2026-11-11。SpektraLab 当前应用源码为 `1952c63537ec576d24422f1065b12495631346a5`；spektrafilm 为 `3bb2c2d2801ff68b92019cf1dbcbb133d60832bc`。本次没有替换材料数据或重新拟合胶片曲线，继续使用随源码提供的引擎与 Android 适配。

SpektraLab 的价值在于整条成像链：解码输入颜色、在胶片响应前调整曝光、通过材料的光谱/感光与密度响应，再经过相纸或正片扫描输出；颗粒和光晕也有模型参数。输入曝光会改变材料响应与色彩关系，不能用最后给照片加亮来等价替代。负片流程的印片曝光归一化，也会使同一 EV 的成片亮度变化小于直觉预期。

这里有个容易混淆的默认值：引擎 `engine/src/core/params.hpp` 默认开启 `auto_exposure`、采用 `center_weighted`，手动曝光补偿0；但当前桌面应用的 `FilmParams.swift` 会为新照片设置自动测光关闭、方法 `balanced`、补偿0。因此不能说“上游软件一打开就一定会自动曝光”。胶片前手动曝光与自动测光是两个独立概念。

## 片屿的新起点

新照片默认：推荐强度75、轻颗粒12.5、胶片曝光手动补偿0，**开启胶片前自动测光，采用上游的保护高光方法**。处理顺序是解码 sRGB → 自动测光及手动 EV → 胶片/印片或扫描 → 混合风格与额外预设 → 用户基础/HSL调节 → 构图和输出。

“调色 → 胶片曝光”直接提供测光开关。用户可关闭它保留原图曝光起点，也可在测光结果上加减±2EV；这些操作可撤销，并随照片、复制配方、命名配方保存。自动测光不是固定加曝光，也可能压暗照片。风格强度0不应用胶片效果、测光或预设，用户自己设置的成片调整仍然保留。

我们选择保护高光而非盲目照搬默认值，是在六类场景上实际运行了关闭、中央加权、平衡、保护高光测光。下表为相同 Portra 400/Endura 材料、640长边、手动EV0时桌面引擎报告的补偿，四舍五入到两位；不是从画面猜出的数值。

| 场景 | 中央加权 | 平衡 | 保护高光 |
| --- | ---: | ---: | ---: |
| 街边人物 | -0.19 | +0.24 | +0.22 |
| 船上抓拍 | -1.10 | -0.63 | -0.63 |
| 阴天海岸 | -0.91 | -0.16 | -0.16 |
| 演出 | +0.94 | +3.05 | +0.28 |
| 雨夜街道 | +0.83 | +1.61 | +0.62 |
| 街头人文 | -0.42 | +0.34 | +0.10 |

实际视觉判断：平衡测光把演出大幅提亮，削弱了舞台气氛；保护高光保留了较多现场明暗。中央加权在抓拍与海岸上压暗较多。保护高光适合作为这组素材的新手起点，但抓拍仍被压暗；它不保证每张都更亮或更好看，开关必须保留。测光无法找回 JPG 已经裁掉的高光或抵消手机的全部 HDR/锐化。

## 75与100的真实含义

75是原v2推荐100的重新定位，**不是胶片准确率75%**。在关闭自动测光、其他参数相同的条件下，新75与旧100输出相同。v3的材料混合权重为 `min(1, strength / 0.75 * 原推荐材料权重)`，额外预设为原预设的 `strength / 0.75` 倍；100可使额外预设到4/3倍，材料逐渐到完整模型。

材料混合不外推到1以上，避免黑白产生反色或把原片颜色重新带回来。对于原推荐材料已为100%的克制复古、柔和黑白，75以上增强的是片屿额外预设：例如黑白的柔化反差、抬升暗部与褪色，不把“更强”一律解释为更饱和或更黑。可关闭额外预设，从材料模型自行创作；该模式的100仍表示完整材料模型。

老照片与旧配方不自动重测光。v2存储数值不改写，只在UI按等效位置显示（旧100显示75）；拖动或输入强度才转为v3。v0/v1保持原版本语义。配方保存测光方式，避免未来默认方法变化后旧作品被重新解释。点击强度旁的数值可以直接输入。

## 验证与可重复性

Android 测试 `ExposureStrengthDeviceTest` 用五张公开测试输入（人物、风光、演出、夜景、抓拍）逐一渲染七款风格：75关闭测光、75开启、100开启，连同输入共110张PNG，记录输入/输出SHA-256、参数及设置。测试断言75关闭测光与旧v2推荐逐像素一致、100有实际增量；另比较实际JNI的两种测光方法输出，并验证黑白无彩色混回、亮暗方向没有反转。测试输入为AI生成的手机摄影风格图，不是历史胶片或真实手机原片；不能用这批图证明模拟的物理准确率。

原尺寸JPG和HEIF验证使用带旋转方向的2304×3456测试文件，通过实际PhotoIO解码、开启新默认测光的Android引擎、基础/HSL调节、PNG保存及读取，逐行比较输出像素。预览约960长边，导出原尺寸；当前每次调用新建引擎会话，测光输入分辨率也可能不同，不能承诺预览与导出逐像素或测光EV完全一致。

本轮具体设备结果、界面截图、哈希与构建记录随v11分发验证材料提供。用户已反馈v10在OPPO上正常；本轮本地真机为红米K80 Pro，不能把该结果扩大为所有安卓设备通过。旧宣传视频展示的是之前版本，不代表新默认测光效果。
